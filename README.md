# LogicForge Studio

**Веб-орієнтована інформаційна система моделювання та симуляції цифрових логічних схем**

Браузерна САПР (CAD) та інформаційна система для інтерактивного проєктування, часового моделювання, синтезу таблиць істинності та версіонування цифрових і мікропроцесорних логічних схем у реальному часі.

---

## 2. Принцип роботи ядра симулятора (Mathematical & Graph Model)

### 2.1. Чотиризначна тристабільна логічна алгебра

Для адекватного моделювання магістралей даних мікропроцесорних пристроїв, відкритих колекторів (наприклад, виводу `DISCH` таймера NE555) та виявлення коротких замикань на спільних шинах реалізовано розширену чотиризначну алгебру Кліні—IEEE 1164 над множиною станів:

$$\mathbb{L}_4 = \{0, 1, Z, X\}$$

де:

- `0` (`LOW`) — низький логічний рівень;
- `1` (`HIGH`) — високий логічний рівень;
- `Z` (`High-Z`) — високоімпедансний третій стан (вимкнений шинний буфер або обірвана лінія);
- `X` (`CONFLICT` / `UNKNOWN`) — колізія активних драйверів на шині або невизначений потенціал.

Для кожного еквівалентного електричного вузла (Net), сформованого системою неперетинних множин (**Disjoint-Set / Union-Find**), діє комутативна та асоціативна **функція розв'язання спільної шини** $\mathcal{R}(S)$ для мультимножини вихідних драйверів $S = \{s_1, \dots, s_k\}$:

$$\mathcal{R}(S) = \begin{cases} Z, & \text{якщо } S = \emptyset \lor \forall s_i \in S : s_i = Z, \\ X, & \text{якщо } (\exists s_i = X) \lor (\exists s_a = 0 \land \exists s_b = 1), \\ 1, & \text{якщо } \forall s_i \in S \setminus \{Z\} : s_i = 1, \\ 0, & \text{якщо } \forall s_i \in S \setminus \{Z\} : s_i = 0. \end{cases}$$

Логічні вентилі підтримують закони поглинання Кліні: нульовий вхід домінує в кон'юнкції ($0 \land Z = 0$, $0 \land X = 0$), а одиничний вхід домінує в диз'юнкції ($1 \lor Z = 1$, $1 \lor X = 1$).

### 2.2. Графова модель, алгоритм Кана (STA) та алгоритм Тар'яна (SCC)

Схема подається орієнтованим мультиграфом $G = (V, E)$, де $V$ — множина логічних елементів, а $E$ — орієнтовані інформаційні траси між вихідними та вхідними пінами через вузли з'єднань.

1. **Топологічне сортування ациклічних ділянок (Kahn's Algorithm, $O(|V| + |E|)$)**:
   Синхронні елементи пам'яті (`D_FLIPFLOP`, `JK_FLIPFLOP`, `COUNTER_4BIT`, `TIMER_555`) виступають межами регістрових трактів. На комбінаційному підграфі $G_{\text{DAG}}$ обчислюються півстепені заходу $\deg^-(v)$, формується топологічний порядок обчислення початкового усталеного стану та виконується **статичний часовий аналіз (Static Timing Analysis — STA)**:
   $$T_{\text{arr}}(v) = t_{\text{pd}}(v) + \max_{(u, v) \in E_{\text{DAG}}} T_{\text{arr}}(u), \qquad T_{\text{crit}} = \max_{v \in V} T_{\text{arr}}(v), \qquad f_{\max} = \frac{1000}{T_{\text{crit}}} \text{ [МГц]}.$$
2. **Пошук зворотних зв'язків за алгоритмом Тар'яна (Tarjan's SCC, $O(|V| + |E|)$)**:
   Для виявлення асинхронних петель (RS-тригери на елементах NOR/NAND, кільцеві автогенератори) обхід у глибину знаходить усі нетривіальні компоненти сильної зв'язності $|C_i| > 1$ або петлі $(v, v) \in E$.

### 2.3. Дискретно-подійне моделювання (Event-Driven Min-Heap) та модель таймера NE555

Поширення сигналів у часі керується чергою подій на основі бінарної купи мінімумів `MinHeap<SimulationEvent>`, упорядкованої лексикографічно за парою $(\tau, \text{seq})$, де $\tau \in \mathbb{N}_0$ — модельний час у наносекундах ($O(\log M)$ на вставку та вибірку).

- При зміні входу елемента $u$ в момент $\tau_0$ обчислюється нове значення виходу $y^* = f_u(\mathbf{x}, Q_u)$. Якщо $y^_$ відрізняється від поточного або запланованого стану, планується подія $(\tau_0 + t\_{\text{pd}}(u), u, y^_)$ з інерційним придушенням коротких імпульсів завад (glitch cancellation).
- Для захисту від незбіжної генерації в петлях із непарним числом інверторів діє детектор граничної кількості перемикань у часовому вікні (`OSCILLATION_GUARD`).
- Для ІМС **NE555** в астабільному режимі інтервали заряду та розряду конденсатора $C$ через резистори $R_1, R_2$ визначаються класичними співвідношеннями компараторів $\frac{1}{3}V_{CC}$ і $\frac{2}{3}V_{CC}$:
  $$t_{\text{HIGH}} = \ln(2)(R_1 + R_2)C, \qquad t_{\text{LOW}} = \ln(2) R_2 C, \qquad f = \frac{1.44}{(R_1 + 2R_2)C}.$$

## 3. Специфікація збереження схеми у JSON

Кожна схема серіалізується у валідований Zod-схемою документ `CircuitDocument` (зберігається у полі `schema_json` типу `JSONB` в PostgreSQL):

```json
{
  "metadata": {
    "schemaVersion": "1.0.0",
    "title": "1-бітний повний двійковий суматор",
    "description": "Комбінаційний суматор на XOR, AND, OR",
    "category": "Комбінаційні схеми",
    "tags": ["суматор", "АЛП"],
    "createdAt": "2026-10-15T10:00:00.000Z",
    "updatedAt": "2026-11-08T10:00:00.000Z"
  },
  "viewport": {
    "panX": 20,
    "panY": 20,
    "zoom": 1.0,
    "gridSnap": true
  },
  "nodes": [
    {
      "id": "n_sw_a",
      "type": "INPUT_SWITCH",
      "position": { "x": 80, "y": 80 },
      "width": 108,
      "height": 56,
      "pins": [
        {
          "id": "OUT",
          "name": "Q",
          "direction": "OUTPUT",
          "offset": { "x": 108, "y": 28, "side": "RIGHT" },
          "state": "1"
        }
      ],
      "properties": {
        "label": "A",
        "propagationDelayNs": 1,
        "switchState": "1"
      }
    }
  ],
  "edges": [
    {
      "id": "e1",
      "sourceNodeId": "n_sw_a",
      "sourcePinId": "OUT",
      "targetNodeId": "n_xor_1",
      "targetPinId": "A",
      "signalState": "1"
    }
  ]
}
```

| Ключова сутність              | Призначення та структура полів                                                                                                                                                                          |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `nodes` (`CircuitNodeData[]`) | Масив елементів схеми з унікальним `id`, типом `ComponentType`, координатами `position {x, y}`, габаритами корпусу, масивом `pins` та словником `properties` (`propagationDelayNs`, RC-параметри тощо). |
| `pins` & `PinOffset`          | Кожен вивід має напрям (`INPUT` / `OUTPUT`), прапорці `inverted` і `clockEdge`, поточний `state` та геометричний `offset {x, y, side}` відносно лівого верхнього кута вузла.                            |
| `edges` (`CircuitEdgeData[]`) | Орієнтовані з'єднання між вихідним (`sourceNodeId`, `sourcePinId`) та вхідним (`targetNodeId`, `targetPinId`) виводами з поточним станом лінії `signalState`.                                           |
| `LogicState`                  | Літеральний тип `'0' \| '1' \| 'Z' \| 'X'`, що відображає чотиризначну логіку в реальному часі.                                                                                                         |

## 4. Інтеграція з Neovim, лінтерами та перевіркою якості коду

Репозиторій містить повний набір конфігурацій для комфортної роботи в **Neovim** (`nvim-lspconfig`, `conform.nvim`, `nvim-lint`):

- `.editorconfig` — автоматичне налаштування відступів (2 пробіли, UTF-8, LF) у Neovim 0.9+.
- `eslint.config.js` — ESLint 9 Flat Config (`typescript-eslint` + `eslint-plugin-react-hooks`).
- `.prettierrc.json` — єдиний стандарт форматування коду.
- `.codespellrc` — автоматична перевірка орфографії у вихідному коді та документації через `codespell`.
- `.nvim.lua` — локальні налаштування буфера проєкту.

### Стандартизовані команди `package.json`

```bash
npm install            # Встановлення всіх залежностей монорепозиторію
npm run dev            # Одночасний запуск shared-types, REST API (4000) та Vite клієнта (5173)
npm run build          # Повна виробнича збірка всіх пакетів
npm run test           # Запуск модульних тестів Vitest (ядро) та інтеграційних Supertest (API)
npm run test:coverage  # Звіт покриття алгоритмічного ядра тестами (>90%)
npm run lint           # Статичний аналіз ESLint
npm run format:check   # Перевірка форматування Prettier
npm run typecheck      # Строга перевірка типів TypeScript у всіх workspaces
npm run spellcheck     # Перевірка орфографії codespell
npm run check          # Повний конвеєр верифікації (spellcheck + format + lint + typecheck + test + build)
```
